两个用户 DLL `vl3vpn.dll`、`ArrayVPNApi.dll`，以及三个从 Windows 系统目录复制的 DLL 构成五个不同目标。每个场景分别以一个新 REA 会话执行两轮目标切换和单函数反编译；前三个和前四个目标分别用于容量 3、4，五个目标用于容量 5 和默认容量 2 的对照。第二轮每个目标的伪代码 `normalized_result` 摘要与事先取得的参考摘要一致；这只验证选定函数，不证明全部分析结果等价。

所有目标均先有隔离的 Checkpoint，测试期间操作系统缓存为热状态；目标 1 的证据确认恢复已有 Program、未重新运行自动分析。时间包括每次 `open_binary` 和 `procedure_pseudo_code` 调用，不包含调用之间的脚本开销。默认容量 2 与容量 5 使用相同的五目标、同一套测试脚本和顺序；两者各测一次，不能据此推断统计稳定性。

内存是按约两秒间隔采样进程家族并求和；工作集可能重复计入共享页且受 Windows 回收影响，私有提交不是物理驻留量，短时峰值可能漏采。容量是每个 REA 会话的目标数量上限，不是内存上限；更大或不同类型的 DLL 可能占用更多。按顺序单次运行，不能作为跨机器的内存预算或速度保证。
